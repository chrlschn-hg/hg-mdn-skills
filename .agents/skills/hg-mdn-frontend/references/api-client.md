# The Generated API Client

Generate MSW handlers and Faker factories from the committed contract with the pinned plugins in [mocking.md](mocking.md).  The tested Kubb plugin pair matters: peer ranges can allow incompatible versions.

Everything the front-end knows about the backend is generated by [Kubb](https://kubb.dev/llms.txt) from the OpenAPI document the .NET build writes.  See the `hg-mdn-backend` skill, `references/openapi-contract.md`, for the C# side.

```text
C# endpoints --dotnet build--> src/api/<project>-api.json --kubb generate--> src/api/generated/
                                  (committed)                                  (git-ignored)
```

- `npm run generate` regenerates; Aspire runs `generate:watch`; `npm test` and `npm run build` regenerate first.
- **Never edit `generated/`.**  Need different output?  Fix the backend (`WithName`, XML docs, `Results<...>`) or `kubb.config.ts`.
- A backend contract change appears here as a changed generated type: let the type checker (`npm run build`) show every call site to update.

## What gets generated

| Output | Contents |
|---|---|
| `generated/clients/<operationId>.ts` | one function per operation: `listNotes`, `createNote`, ... (from the backend's `WithName`) |
| `generated/types/<Schema>.ts` | request, response, and error types (`CreateNoteRequest`, `NoteResponse`, `ApiError`) and per-operation option/response types |
| `generated/zod/<operation>RequestSchema.ts`, `<schema>Schema.ts` | **Zod 4 schemas** for requests and responses, with the contract's limits (`max(200)`, required fields) and `.describe()` text; use them to validate forms (`forms.md`) |
| `generated/.kubb/client.ts` | the shared client: `client`, `ResponseError`, `withUnwrap`, config and interceptors |

`generated/clients/createNote.ts` (generated):

`src/app/src/api/generated/clients/createNote.ts`

```ts
/**
* Generated by Kubb (https://kubb.dev/).
* Do not edit manually.
*/

import type { Options, Unwrappable, RequestResult } from '../.kubb/client'
import type { CreateNoteOptions, CreateNoteResponses } from '../types/CreateNote'
import { client, withUnwrap } from '../.kubb/client'

/**
 * @description Creates a note with a title and optional body, and returns it. The title is
 * trimmed, required, and limited to 200 characters; a blank or overlong title is
 * rejected with a specific error code.
 * Pass `notebookId` to file the note in an existing notebook. Responds with 404 and
 * the code `notebook_not_found` when that notebook does not exist; omit it to leave
 * the note unfiled.
 * @summary Create a note.
 * {@link /api/notes}
 */
export function createNote<ThrowOnError extends boolean = true>(options: Options<CreateNoteOptions, ThrowOnError>): Unwrappable<RequestResult<CreateNoteResponses, ThrowOnError>> {
  const { client: request = client, ...config } = options

  return withUnwrap(request({ method: 'POST', url: '/api/notes', ...config, throwOnError: config.throwOnError ?? true }) as Promise<RequestResult<CreateNoteResponses, ThrowOnError>>)
}
```

**Read the JSDoc before you call a function.**  The backend's summary and description are generated into it (`@summary`, `@description`) and show on hover: they say what the operation is for, its rules and limits, and which situations produce which error code.  They are the API documentation; if they are missing or unclear, fix them in the backend (`WithDescription`).

Import the function and the types you need directly (there is no barrel file):

```ts
import { createNote } from "@/api/generated/clients/createNote";
import type { NoteResponse } from "@/api/generated/types/NoteResponse";
```

## Calling it

```ts
const body = await createNote({ body: { title: "Hello" } }).unwrap();   // NoteResponse (the 2xx body)
const page = await listNotes().unwrap();                                // NoteListResponse
```

- Every function returns a promise with `.unwrap()`, which resolves to the success **body**.  Use it in `src/queries` (the only callers; the session store through `queries/session.ts`).
- By default (`throwOnError` true) a non-2xx response **throws `ResponseError`**, so a resolved call always means success.  `ResponseError` has `status`, `statusText`, `data` (the parsed error body), `request`, `response`.
- Request data goes in the options object: `{ body }`, `{ path: { id } }`, `{ query: { ... } }`, `{ headers }`, plus `{ signal }` for an `AbortController`.
- Need to branch on status instead of catching?  Pass `{ throwOnError: false }`: the result carries `status`, `data`, and `error`, discriminated by status.
- `Date` fields arrive as ISO strings (`checkedAtUtc: string`); parse at the edge (`new Date(value)` or `dayjs`) when you need arithmetic.

## Errors and `SaveResult`

The backend returns **`ApiError`** (`{ code, message }`) for expected failures and problem details for unexpected ones.  One helper file turns both into something a page can show:

`src/app/src/api/errors.ts`

```ts
import { ResponseError } from "@/api/generated/.kubb/client";

/**
 * The backend's expected-failure body (the `ApiError` record in `<PROJECT>.Api`): a stable
 * machine-readable `code` to switch on and a `message` fit for display.  Declared here rather
 * than imported from `generated/` because the generated type only exists once an endpoint
 * returns it.
 */
export type ApiError = { code: string; message: string };

/** True when `data` has the shape of the backend's expected-failure body (`ApiError`). */
function isApiError(data: unknown): data is ApiError {
  return typeof data === "object" && data !== null && "code" in data && "message" in data;
}

/**
 * The backend's `ApiError` (`{ code, message }`) when `err` is a failed API call that carries
 * one; `null` for anything else (network failures, unexpected 500s).  Switch on `code`, not on
 * the message.
 */
export function toApiError(err: unknown): ApiError | null {
  return err instanceof ResponseError && isApiError(err.data) ? err.data : null;
}

/** True when `err` is a failed API call that answered 401: nobody is signed in. */
export function isUnauthorized(err: unknown): boolean {
  return err instanceof ResponseError && err.status === 401;
}

/** A user-facing message for any thrown value, preferring the backend's own message. */
export function errorMessage(err: unknown, fallback: string): string {
  return toApiError(err)?.message ?? (err instanceof Error ? err.message : fallback);
}

/** The message for a failed load, or `null` when nothing failed: what `AsyncContent`'s `error` takes. */
export function errorText(err: unknown, fallback: string): string | null {
  return err == null ? null : errorMessage(err, fallback);
}

/**
 * The outcome of a write action that the caller must react to (close a form, mark a field).
 * Actions return this instead of throwing: `ok` on success; otherwise the backend's stable error
 * `code` (when it sent one) and a message fit for display.
 */
export type SaveResult = { ok: true } | { ok: false; code: string | null; message: string };

/** Converts a thrown value into the failure side of a {@link SaveResult}. */
export function toSaveFailure(err: unknown, fallback: string): SaveResult & { ok: false } {
  return {
    ok: false,
    code: toApiError(err)?.code ?? null,
    message: errorMessage(err, fallback),
  };
}
```

- Switch on `toApiError(err)?.code` (stable, `snake_case`: `invalid_title`, `title_too_long`) for behavior; show `message` to people.
- Anything else (network failure, 500 problem details) falls back to a generic message: `errorMessage(err, "Could not save the note.")`.  The 500 body carries a `traceId` for the backend team.
- **`SaveResult`** is what a mutation composable returns: `{ ok: true }` or `{ ok: false, code, message }` (`code` is `null` when the failure was not an `ApiError`); `toSaveFailure(err, fallback)` builds the failure.  The caller shows `message` and maps `code` to a form field (`forms.md`).  Never match on message text.
- **`isUnauthorized(err)`** is true for a 401.  Cross-cutting handling lives in `configureApiClient`, which dispatches a window event `api:unauthorized` for any 401; the router listens (`routing.md`).  Queries and stores do not redirect.
- `ApiError` is defined locally in `errors.ts` (the generated `ApiError` type exists only when an operation declares it); keep it structurally the same as the backend's.

The shipped `errors.test.ts` checks error mapping.  Use MSW for new tests of the generated client and HTTP behavior (`mocking.md`).

## Configuring the client

The generated calls are **relative** (`/api/health`) and the config has no `baseURL`, so the SPA calls whichever origin served it (the backend in production, the Vite proxy in development; `config-deploy.md`).  Everything is configured once, before the app mounts.  `configureApiClient` lets `VITE_API_BASE_URL` set a base URL at build time, only for a front-end hosted apart from the API (`config-deploy.md`), and is **idempotent**: calling it again replaces its 401 interceptor instead of stacking another.

`src/app/src/api/setup.ts`

```ts
import { client } from "@/api/generated/.kubb/client";

// Id of the interceptor this module registered, so configuring twice (HMR, tests) replaces it
// instead of stacking a second copy.
let unauthorizedInterceptor: number | undefined;

/**
 * One-time configuration of the generated client; call it from `main.ts` before the app mounts.
 * Safe to call again: it replaces what it registered before.
 */
export function configureApiClient() {
  // The generated calls are relative (`/api/...`): same-origin in production (the backend serves
  // the SPA) and in development (the Vite proxy).  Only when the SPA is hosted apart from the API
  // set `VITE_API_BASE_URL` when building (see "Hosting apart from the API" in `config-deploy.md`:
  // it also needs CORS on the backend, and `credentials: "include"` for cookie authentication).
  const baseURL = import.meta.env.VITE_API_BASE_URL;

  if (baseURL !== undefined) {
    client.setConfig({ ...client.getConfig(), baseURL });
  }

  // Interceptors run in registration order.  Error interceptors see every non-2xx `ResponseError`
  // before it is thrown: the place for cross-cutting reactions such as "401 -> sign in".
  if (unauthorizedInterceptor !== undefined) {
    client.interceptors.error.eject(unauthorizedInterceptor);
  }

  unauthorizedInterceptor = client.interceptors.error.use((error) => {
    if (error.status === 401) {
      window.dispatchEvent(new CustomEvent("api:unauthorized"));
    }
    return error;
  });
}
```

- `client.setConfig({...})` takes `baseURL`, `headers`, `credentials`, `throwOnError`, `auth` (a bearer token or a function returning one, for operations that declare security).  Spread `client.getConfig()` so you extend rather than replace.  It **merges**: a key you set stays set until you name it again (tests restore `baseURL` explicitly for that reason).
- `client.interceptors.request | response | error` each take `.use(fn)`; `fn` receives the value and returns it (modified or not).  `.use` returns an id for `.eject(id)`.
- **Query errors are typed.**  `src/api/colada.d.ts` types every query and mutation `error` as `ResponseError`, so `error.value?.status` and `error.value?.data` need no cast (a network failure is a plain `Error` at runtime: `status` is then `undefined`).  `errorText(error.value, fallback)` (`errors.ts`) turns a query's `error` into the string `AsyncContent :error` takes, or `null` when nothing failed (`data-loading.md`, `ui-states.md`).

## When `fetch` is acceptable

Use the generated client for every call.  Call `fetch` (or `EventSource`) directly only for an endpoint OpenAPI cannot describe, typically **server-sent events** or streaming responses.  Put it in one small module (in `src/queries` when a query or mutation calls it), type the payload yourself, prefix the path with `client.getConfig().baseURL ?? ""` (undefined by default: same-origin) and reuse `credentials` so it follows the same configuration, and test its network behavior with MSW.

## Kubb configuration

The scaffold uses this configuration.  See [mocking.md](mocking.md) for version pins and test setup.

```ts
import { defineConfig } from "kubb";
import { pluginTs } from "@kubb/plugin-ts";
import { pluginFetch } from "@kubb/plugin-fetch";
import { pluginFaker } from "@kubb/plugin-faker";
import { pluginMsw } from "@kubb/plugin-msw";
import { pluginZod } from "@kubb/plugin-zod";

// Reads the OpenAPI document that the backend build writes (see `OpenApiDocumentsDirectory` in
// `<PROJECT>.Runtime.csproj`) and generates typed fetch clients.  Run: `npm run generate`.
export default defineConfig({
  input: "./src/api/<project>-api.json",
  output: {
    path: "./src/api/generated",
    clean: true,
  },
  plugins: [
    pluginTs({
      output: {
        path: "./types",
        mode: "directory",
      },
      enum: {
        type: "asConst",
      },
      optionalType: "questionTokenAndUndefined",
    }),
    // Zod schemas from the same OpenAPI constraints (maxLength, required, ...): form validation
    // that cannot drift from the backend.  Import from `@/api/generated/zod/<operation>Schema`.
    pluginZod({ output: { path: "./zod", mode: "directory" } }),
    // https://kubb.dev/plugins/plugin-fetch/reference/options
    // No `baseURL`: the OpenAPI paths already start with `/api`, so the generated calls are
    // relative and the SPA talks to whatever origin served it (the backend in production, the
    // Vite dev proxy locally; see `vite.config.ts`).
    pluginFetch({
      output: {
        path: "./clients",
        mode: "directory",
      },
    }),
    pluginFaker({
      output: { path: "./mocks", mode: "directory" },
      typeMode: "schema",
      seed: [1],
      printer: {
        nodes: {
          string(node) {
            if (node.pattern || node.format || node.content || node.min !== undefined) {
              return this.base(node);
            }
            const words = "faker.lorem.words({ min: 2, max: 5 })";
            return node.max === undefined ? words : `${words}.slice(0, ${node.max})`;
          },
        },
      },
    }),
    pluginMsw({
      output: { path: "./handlers", mode: "directory" },
      parser: "faker",
      handlers: true,
    }),
  ],
});
```
